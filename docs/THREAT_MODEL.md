# Threat model

Assets: the user's machine and CI runner, secrets in compose files and manifests, the integrity of review output
(Markdown summaries, SARIF, generated DSL), and the trust reviewers place in the report.

| Threat                                                                                          | Mitigation                                                                                                                                                                                   | Test                                     |
| ----------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------- |
| Model runs code (`!script`, `!plugin`) or fetches content (URL `!include`, `workspace extends`) | Refused and reported as `model-invalid` (blocks by default); never evaluated or fetched. Local `!include` is not followed (limitation). CALM `$ref`s are not followed.                       | `security.test.ts` (A9), `units.test.ts` |
| Code execution through the repository                                                           | No `child_process`, `vm`, `eval`, dynamic `import()` or network modules in `src/` (lint + static test). Helm, Kustomize, Terraform never rendered. Config is JSON only.                      | `security.test.ts`                       |
| Secrets in environment values                                                                   | Values are reduced in memory to the host they name; only variable names appear as evidence. All output strings are token-redacted.                                                           | `security.test.ts` (A9)                  |
| YAML bombs, unknown tags, duplicate keys                                                        | YAML 1.2 core schema, ≤ 100 alias expansions, unique keys; unknown tags are read as plain data, never resolved                                                                               | `security.test.ts`                       |
| Path tricks (symlinks, `..` in build contexts, model references, Action inputs)                 | `lstat`, symlinks never followed; paths normalized and confined to the root; Action rejects absolute and `..` paths                                                                          | `security.test.ts`, `action.test.ts`     |
| Injection through names into Markdown/HTML, DSL or SARIF                                        | Names and paths as code spans; free text escaped; `@` neutralized; control characters made visible. DSL strings escaped and control characters removed; identifiers generated, never copied. | `rendering.test.ts` (A9)                 |
| Resource exhaustion                                                                             | 20,000 entries, depth 20, 1 MiB per parsed file, 1 MiB model, 64 MiB graph/report, 5,000 findings, 5 evidence items per finding, 60k-character Markdown                                      | `units.test.ts`, `rendering.test.ts`     |
| Model text instructs a downstream AI reviewer                                                   | Model text is data; only documented `commons.*` keys change behavior. The Markdown report starts with an untrusted-data notice.                                                              | `rendering.test.ts`                      |
| Gaming the policy (edit the model, config or ignores in the same PR)                            | Config and ignores listed in the report; CODEOWNERS guidance                                                                                                                                 | `docs/CONFIG.md`                         |
| Over-trust ("no findings, so the model is right")                                               | `static-analysis-only` limitation in every report; unobserved relationships are `unknown`; name matches are hypotheses; no score                                                             | acceptance                               |
| Trojan Source in this repository                                                                | Test rejects bidi/invisible characters in `src/` and `test/`                                                                                                                                 | `security.test.ts`                       |
| Action privilege misuse                                                                         | `pull_request` + `contents: read`; env-passed inputs; no tokens used                                                                                                                         | `action.test.ts`                         |

Residual risks: heuristics (name matching, directory components, technology families, vendor tables) produce false
positives and negatives — all such findings are hypotheses. Redaction is pattern-based. The DSL reader handles a
documented subset; models outside it are partly skipped (limitations listed).
